# v4 candidate: AZ-style preflop on top of v3 (branch yifan/v4-az-preflop)

Base: v3 (main, SHA-256 2a831f88…). Postflop range weighting, exposed-card conditioning and discard ties unchanged.

Changes:
- Preflop replaced by `_preflop` (table lookup, no Monte Carlo). `preflop_policy.json` (exported by
  `research/analysis/export_policy.py`) holds per-combo [percentile, bucket] and the FULL jam/fold
  bucket policy (jam_by_bucket, call_by_bucket); bucket probability >= 0.5 = act (deterministic).
  - Unopened, eff <= 15 bb: solver jam/fold policy by table size (nearest of 2/3/4/6/8), position, depth.
  - Unopened, deeper: open 2.5 bb (+1 bb per limper) below percentile HJ .26 / CO .34 / BTN .65 / SB .70 / earlier .17.
  - Facing one raise: re-raise below .05 (.06 SB, .08 BB; jam if eff <= 25 bb, else 3x), call below .10 (.20 SB, .30 BB).
  - Facing an open jam: solver call policy when <= 20 bb; otherwise call below .10 (.35 if price <= 30%).
  - 3-bets+ / big multi-raise spots: continue only the top 3–6%.
  - Uncovered states or any exception fall back to the v3 equity logic.
- Exposure: show the retained card that pairs / suits the board less, then the lower rank.
- Value bet size 1/2 -> 2/3 pot.

Known limits: chip EV (no ICM), equal-stack solver used with effective stacks, no multiway all-in model,
thresholds above 15 bb are AZ-derived heuristics, not solved.
